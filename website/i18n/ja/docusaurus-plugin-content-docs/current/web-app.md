# Web アプリ

ターミナルで `iac-code` を実行すると、ローカル Web アプリが起動し、ブラウザが開きます。初回は設定画面で LLM プロバイダーと Alibaba Cloud の認証情報を設定してください。

デスクトップと Web は会話と設定を共有します。他のインターフェースで作成した会話は読み取り専用の場合があります。表示と続行は[セッション](./cli/sessions.md)を参照してください。

## インストール

標準インストールには Web アプリと HTTP ランタイムの依存関係が含まれます。`[http]` エクストラは互換性のための別名として残りますが、個別のインストールは不要です。リポジトリから実行する場合は `uv sync` だけで準備できます。

```bash
pip install iac-code
```

## Web アプリの起動

ターミナルからサーバーを起動します：

```bash
iac-code web
```

デフォルトでは `127.0.0.1:8766` にバインドし、既定のブラウザで `http://127.0.0.1:8766` を開きます。

| オプション | デフォルト | 説明 |
|---|---|---|
| `--host` | `127.0.0.1` | HTTP サーバーホスト。ローカルモードではループバックアドレスを使用します。他の IP アドレスには `--access-token-file` が必要です。 |
| `--port` | `8766` | HTTP サーバーのポート。 |
| `--open` / `--no-open` | `--open` | 起動時にブラウザを開きます。`--no-open` で無効化できます。 |
| `--debug`, `-d` | `false` | 今回の実行でサーバーのデバッグログを有効にします。 |
| `--access-token-file <path>` | — | API 通信を暗号化する明示的なリモートアクセス用のトークンファイル。 |

```bash
iac-code web --port 9000 --no-open
```

### セキュリティ

`--access-token-file` を指定しない場合、サーバーはループバックホスト（`127.0.0.1`、`localhost`、`::1`）のみを受け付け、ローカルリクエストを検証します。明示的なトークンモードでは他の IP アドレスも使用でき、API リクエストは暗号化トークン通信で保護されます。

## 既存の ROS テンプレートをデプロイする

1. [クラウド認証情報](./configuration/alibaba-cloud-credentials.md)を設定し、テンプレートのあるプロジェクトで会話を開きます。

2. `@` でファイルを選び、テンプレートの確認と必要なパラメーターの提示を依頼します。

3. リージョン、スタック名、パラメーター値を伝え、作成前の検証を依頼します。

4. 検証結果と予定された変更を確認し、スタックの作成を依頼します。

5. クラウド API の承認カードが表示されたら操作を確認して許可または拒否します。作成を許可すると課金対象リソースが作られる場合があります。

6. 会話でスタック ID、進捗、結果を確認します。失敗した場合は同じ会話で具体的なエラーの調査を依頼します。

## 画面の概要

### セッションサイドバー

サイドバーには保存済みの会話がプロジェクト別に表示されます。次の操作ができます。

- **新しいチャット**を開始し、入力欄の下でプロジェクトを選びます。
- 会話を**検索**する、またはコマンドパレットを開いてコマンドを実行する。
- 会話を**ピン留め**、**名前変更**、**アーカイブ**し、アーカイブ済みの会話を閲覧する。

Web、デスクトップ、headless は保存済みの会話を共有します。続行と名前の変更は[セッション](./cli/sessions.md)を参照してください。

### コンポーザー

入力欄で作業を説明し、画面のコントロールで会話の動作を選択します。

- アクティブなセッションの**モデルとプロバイダー**の選択。
- 対応モデルで拡張推論を有効・無効にする**思考**トグル。
- ツール操作の承認方法を決める**権限モード**のコントロール。
- マルチモーダルモデル向けの**画像添付**。
- `/` または `$` の候補から**スキル**を選び、**`@` ファイル参照**で作業ファイルを追加します。

### 通常チャットとパイプラインモード

会話の作成時にモードを選び、パイプラインモードの場合はパイプラインも選択します。同じアプリ内の会話で異なるモードを使用でき、サーバーの再起動は不要です。

セッションは通常チャットとして、または**パイプライン**モードで動作します。通常チャットはアシスタントの返信、ツール呼び出し、結果をインラインでストリーミング表示します。パイプラインモードでは、パイプラインの実行に合わせてステップのタイムライン、診断、図、デプロイの進捗、クリーンアップ、引き継ぎの詳細を表示するワークスペースが追加されます。パイプラインの機能は[パイプラインモード](./automation/pipeline-mode.md)を参照してください。

[`selling_solution_first` パイプライン](./automation/solution-first-pipeline.md)は、このワークスペースで 3 段階の購入フローを提供します。候補アーキテクチャを比較し、選択したソリューションを実装して、確認後にデプロイします。ツール承認は、それを要求したステップの下にローカライズされた権限カードとして表示されます。セッションを復元すると、未処理の承認も同じステップに戻ります。

### ツールと承認

ツール呼び出しはトランスクリプト内にカードとして表示されます。ツールが承認を必要とする場合、承認リクエストがインラインで表示されます。コンポーザーで設定した権限モードによって、確認を求められるタイミングが決まります。

### 設定

デスクトップと Web は同じ画面を使用します。日常の操作には設定、会話メニュー、入力欄のコントロールを使います。

- Alibaba Cloud の**クラウド認証情報**（[Alibaba Cloud 認証情報](./configuration/alibaba-cloud-credentials.md)を参照）。
- **モデル**とプロバイダーの構成（[LLM プロバイダー](./configuration/llm-providers.md)を参照）。
- **MCP プラグイン**（[MCP 連携](./mcp/overview.md)を参照）。
- **メモリ**の確認と管理。

### 表示言語

Web アプリは 7 つの言語 —— English、簡体中国語、日本語、Français、Deutsch、Español、Português —— に対応しており、設定から選択できます。選択内容は保存され、以降のセッションで使われます。

## CLI との関係

Web 版、デスクトップ版、ヘッドレス実行は、プロバイダー、認証情報、スキル、ツール、セッションを共有します。設定画面でモデルとクラウドアクセスを一度設定すれば、各入口で再利用できます。
