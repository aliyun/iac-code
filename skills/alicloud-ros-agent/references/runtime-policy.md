# Runtime policy and remote CLI diagnostics

The bridge reads an optional `config.json` in the Skill root beside `SKILL.md`. If it is absent, the transport defaults to `code`, the endpoint defaults to `ros.aliyuncs.com`, both Agent modes are allowed, Thinking is enabled, the Credentials SDK default chain selects the effective identity, and the temporary loopback manager exits 60 seconds after the last SSE worker and manager request become idle. The file accepts these settings:

```json
{
  "transport": "code",
  "endpoint": "127.0.0.1:56124",
  "allowedAgentModes": ["normal", "pipeline"],
  "managerIdleSeconds": 60,
  "enableThinking": true,
  "debug": false,
  "aliyunCLIProfile": ""
}
```

When `transport` is `aliyun_cli`, add `"aliyunCLIExecutionMode": "local"` or `"remote"`; do not add that field to a `code` transport configuration.

- `transport` accepts exactly `code` or `aliyun_cli`. `code` is the default: it delegates identity resolution to the Credentials SDK default chain unless a Profile is explicitly pinned, in which case the SDK Profile provider owns resolution and refresh. It signs and sends StartChat or StopChat to the configured endpoint while exposing SSE events as they arrive. `aliyun_cli` invokes only the ROS plugin's validated `start-chat` and `stop-chat` operations. SDK imports are lazy and never occur in `aliyun_cli` mode. There is no silent fallback between transports or from a pinned Profile to the default chain.
- `aliyunCLIExecutionMode` accepts exactly `local` or `remote`, defaults to `local`, and is valid only with `transport: "aliyun_cli"`. `local` uses the native local CLI, Profile, and plugin installation. `remote` treats the same-name `aliyun` executable as a host-provided executor whose routing and execution mechanism is outside the bridge contract; the bridge permits only `aliyun ros start-chat` and `aliyun ros stop-chat`, never CLI management or another API operation. Remote mode does not read or pass a local Profile, does not infer a local region, rejects `aliyunCLIProfile`, and requires a public `*.aliyuncs.com` endpoint. All prompt and response payloads are passed inline; never pass a file-backed CLI parameter to the remote command.
- `aliyunCLIForwardEnv` is valid only for remote CLI execution and accepts at most 16 unique, non-secret environment variable names. It defaults to `[]`; each remote implementation must list any required names explicitly in `config.json`. Every foreground `start`, `follow`, `continue`, `respond`, or `cancel` uses current values for new CLI invocations, never stale manager/worker-inherited values. Values are never persisted or returned. The foreground remains alive until its CLI call finishes, including host approval and buffered output; the observation timeout applies only to idle waiting. If the foreground disappears, the local reader stops without sending StopChat. A new foreground command may reconnect only with a committed SessionId/event ID, never by replaying Query. Forwarding a value does not renew its host-owned execution context; report an expired-context failure without blindly retrying. The bridge does not prescribe the host's authorization mechanism.
- Managed remote CLI projections batch ordinary status/text deltas up to 256 events, 1 MiB, or five seconds, and flush at connection EOF/error before reconnect. The first recovery anchor, permissions, milestones, artifacts, errors, and final/terminal boundaries flush immediately. A batch rechecks request ownership, sideband ownership and cancellation under the job lock, appends/fsyncs its event spool once, then atomically saves job state and cursor once. A crash can lose recent uncommitted progress; the durable cursor never advances ahead of the spool, so a resumable stream can replay from that checkpoint without duplicating spooled events. Do not assume that cloud replay retention is unlimited. Code and local CLI keep per-event commits.
- A remote CLI `SSE connection lost` transport error reconnects from the current request's committed SessionId/event ID, without replaying Query. Three consecutive interrupted attempts without a new event stop automatic recovery; new committed events reset that budget. A delivered terminal event remains authoritative. Without a current-request recovery anchor, including after answering a question, the bridge reports `missing_recovery_anchor` and an unknown cloud outcome. A known SessionId or a previous request's cursor is insufficient. No other API probe, OSS download, synthetic SSE cursor, automatic permission/selection, answer replay or replacement job is allowed. Code/local CLI are unchanged. `recovery-decision` debug records contain no Query.
- Explicit cancellation fences the local reader and prevents further StartChat/reconnect dispatch. A subsequent `follow` reports cached job state immediately, with the last `stopStatus` and `stopRequestId`; its `wait-seconds` is not a cloud cancellation polling interval. `Stopping` confirms acceptance only, and a retained StartChat `wireState` may predate cancellation. The bridge has no read-only cloud cancellation-status API; do not repeat StopChat, replay Query or infer completion to fill that gap. Independent read-only cloud verification is needed when a final status is unavailable.
- Only remote CLI execution removes trailing CR/LF characters from the Query and replaces remaining CRLF, CR, and LF line breaks with spaces before invoking `aliyun`. This compatibility rule also applies to YAML and code supplied in prompts; it does not preserve their multiline formatting. The prompt file, stored prompt, code transport, and local CLI Query remain unchanged.
- `debug` is a boolean and defaults to `false`. When enabled for a new remote CLI job, it appends bounded, redacted StartChat diagnostics (including reconnects) to `<workspace>/.ros-agent-debug/remote-aliyun-results.jsonl`: stdout, stderr, parsed event IDs, and execution outcomes. It does not log the command or input prompt, and credentials, forwarded HIL values, and returned history are redacted. Logging failures do not change execution. Local CLI and code transports do not create this log. The job preserves this setting for later turns; an installation administrator may enable it for troubleshooting and start a new job. Treat the log as sensitive diagnostic data even after redaction.
  For managed remote CLI jobs, bounded stdout/stderr snapshots are logged in a batch after the CLI result is published; bulk logging does not delay EOF detection or reconnect. `cli-result` records output byte counts, CLI elapsed time and result-publication delay; `end` records attempt elapsed time and the committed cursor; `debug-complete` records bulk logging elapsed time. Records from different processes may arrive out of order: correlate by `invocationId`, record kind and timestamp, not file order alone.
  `cli-result.queueToLaunchMs` measures mailbox enqueue to actual CLI launch, including foreground wait and supervisor setup (wall-clock approximation, clamped to zero). `interruptReason` distinguishes a vanished foreground from another local reader stop. Each `end` summarizes `outputReadElapsedMs` (input wait/read, including due idle flushes for managed remote CLI), `parseElapsedMs` (parser work excluding input wait and consumer work), `eventProcessElapsedMs` (event handling, including `projectionElapsedMs` for the projection callback), and `parsedEventLogElapsedMs`. `projection-batch` records durable `flushCount`, `flushElapsedMs` and batch limits, including idle/EOF flushes outside the callback. These elapsed, overlapping phases must not be added together. `completeEventCount` includes decoded replay envelopes; `committedEventCount` counts durably committed events, not merely buffered events; `replayedEventCount` counts skipped events. `committedCursor` is durable, while `sequenceAdvance` measures accepted stream progress. Counters reset per invocation and contain no prompt or HIL value.
- `endpoint` fixes the ROS endpoint for every StartChat and StopChat request in a managed job. A conflicting `--endpoint` is rejected, so do not try to override this local policy. Public endpoints must be `*.aliyuncs.com` hostnames. For local integration tests only, `localhost:<port>` and `127.0.0.1:<port>` are accepted; both transports use HTTPS and skip certificate verification only for those loopback addresses.
- `allowedAgentModes` is a non-empty allowlist containing `normal`, `pipeline`, or both. Do not invoke or suggest a mode excluded by this list.
- `managerIdleSeconds` is an integer from 1 through 86400. It defaults to 60. Active StartChat/CLI work—including approval wait, output parsing and concurrent permission-response work—prevents idle shutdown. A remote parser parked solely for a new foreground command does not: the loopback manager may exit, while the parser retains its in-memory stream summary and launches no API operation. Each manager request refreshes activity. Later managed commands restart the manager while preserving job state. The host tool's own timeout must cover approval and execution; the bridge cannot extend it. Host interruption stops the local reader, not the cloud task.
- `enableThinking` is a boolean and defaults to `true`. It fixes `EnableThinking` for the whole managed job; do not pass `--no-thinking` or try to override it per request.
- `aliyunCLIProfile` is an empty or exact CLI Profile name and defaults to empty. In code mode, empty uses the Credentials SDK default chain. A non-empty value pins that Profile for code transport or local CLI execution and fails instead of falling back when the Profile is unavailable. It is invalid in remote CLI execution. Do not pass a conflicting `--profile`.

Unknown fields, invalid values, and duplicate modes fail closed. Never edit `config.json` during an infrastructure task or store credentials in it; it is an administrator/user installation policy.
