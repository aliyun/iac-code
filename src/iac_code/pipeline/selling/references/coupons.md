# 阿里云优惠券查询与预算判断

## 使用原则

用户为部署方案询问优惠券、代金券或抵扣预算时，保留部署目标和规格，按需查询当前账号的券及适用条件。不要仅凭“学生券”“通用券”或面值，承诺可以用于目标配置，也不要因为用券问题中断部署规划。

可用、不适用或待确认只是用券结果，不代表用户取消部署；回答后以 `status: awaiting_selection` 保留候选等待选择，不提交 `rejected`。

券面值、剩余可抵扣金额与用户愿意补付的现金是三件事。只有用户明确要求不补现金时，才把可确认的抵扣额度作为可覆盖费用的上限；未明确时不要自行认定愿意补差价。无需为普通部署查询优惠券。

## 查询优惠券

使用当前会话的云凭证，只查询当前账号，不设置跨账号查询参数：

```python
aliyun_api(product="BssOpenApi", version="2023-09-30", action="DescribeCoupon",
           region_id="cn-hangzhou", params={"CurrentPage": 1, "PageSize": 20})
```

返回 `Data` 为券数组，`CurrentPage`、`PageSize`、`TotalCount` 表示分页。需要继续寻找目标券时递增 `CurrentPage`；未读完列表时不能宣称账号没有该券。不要只按面值选择券；结合用户说明、券类型、状态和限制识别，多个候选无法区分时再澄清。不同券可能省略部分字段，缺失值保留未知，不当作零余额、无限制或已满足资格。

| 信息 | 返回字段与处理 |
|---|---|
| 券标识与类型 | `CouponId`、`CouponType`、`CouponTypeName`；不把不同类型的券都当作现金余额 |
| 金额 | `Amount` 为面值，`RemainAmount` 为余额，金额为字符串；计算时使用十进制金额并核对 `Currency` |
| 状态与期限 | `Status`、`StartTime`、`EndTime`；时间带时区，状态与当前时间均需核对，不能只看余额 |
| 消费场景 | `YhOrderTypes`，核对是否包含本次新购、续费或按量付费账单等场景 |
| 金额与购买时长限制 | `MoneyLimit`、`OrderTimeRule`；仅使用返回的明确规则，空值不等于无限制 |
| 首购等限制 | `FirstBuy`、`Remark`；有首购限制不代表当前账号已经满足资格 |
| 商品范围 | `ItemNames`、`SuitItemType`，必要时按下节查询编码；不能忽略白名单或黑名单语义 |

适用场景和门槛按该张券的实际字段判断，不根据券类型统一推断“抵用券无门槛”或“满减券不能用于按量付费”。

## 查询适用商品

用上一接口返回的真实 `CouponId`，不要猜测或复用示例 ID：

```python
aliyun_api(product="BssOpenApi", version="2023-09-30", action="DescribeCouponItemList",
           region_id="cn-hangzhou", params={
               "CouponId": coupon_id, "CurrentPage": 1, "PageSize": 20
           })
```

`Data` 为商品列表，每项包含 `Code` 和 `Name`，同样按 `TotalCount` 分页。结合该券的 `SuitItemType` 解释结果：`white` 表示指定商品适用，`black` 表示指定商品不适用，`all` 表示全产品通用范围；不能把黑名单中的商品当成可用商品。

商品编码和名称不是实例规格清单。即使包含 ECS，也不能仅凭这一项确认所有 GPU 规格、地域、付费方式或活动渠道均可用；缺少这些条件的证据时明确写“目标配置适用性待确认”。

## 判定结果

- **明确不可抵扣**：券已过期、用尽或作废，或者当前方案违反已返回的付费方式、商品排除、GPU 限制、金额门槛等规则。该券对本次费用的可抵扣金额为 0，不能再假设“也许仍能抵扣”。`Status` 为 `EXPIRED` 或 `EndTime` 已早于当前时间时，即使 `RemainAmount` 仍有数字，也不是有效余额；若只有这一张券，已知的本次费用需全部另付现金。
- **条件性可抵扣**：券有效且余额、适用商品及所有已知限制均匹配时，按下面的费用范围计算；仍保留实际结算说明。
- **待确认**：查询失败或缺少判断目标配置所必需的信息。不要把缺失信息当成已满足，也不要把已经明确不满足的条件重新写成待确认。适用性未确认时，可抵扣金额和需补现金也标为待确认，不能填入看似确定的金额后只在备注中说明未知；如展示假设计算，每个相关金额须明确标注“若适用”等前提。

## 结合方案解释费用

- 保持配置、地域、数量、计费方式和使用时长一致，再比较费用与可抵扣额度。按小时租用时使用有依据的按量单价，不用包月价除以固定小时数替代。
- 分别说明资源粗估、已确认的券余额与适用条件，以及未确认的抵扣范围。优惠券余额不是折后资源单价，不直接从月费中减掉券面值来生成“每月优惠价”。
- 只有代金券的适用范围及其限制已确认、且预计费用全部在可抵扣范围内时，才可给出条件性估算：预计需补现金为 `max(预计费用 - 可用余额, 0)`；仍注明实际抵扣以订单或账单为准。满减、折扣、门槛、部分费用不适用或多券叠加均不得套用该简式。
- 仅明确按小时付费、未给出使用时长时，先展示小时粗估。只有抵扣条件足够明确时，才估算余额可覆盖的大致时长，并列出未覆盖的云盘、网络等费用；不能承诺券用完就自动停机或不再扣费。

## 查询失败与能力边界

接口成功但列表为空，只表示本次查询未返回券；权限不足、认证失败、分页未完成或服务异常都不能解释为没有券。保留当前部署方案，说明具体未知项，不编造抵扣结果。

用户明确要求重新查询或换用另一张券，而本轮查询失败时，不得把此前成功查询的券当成本轮依据；当前券余额、可抵扣金额和需补现金均保留待确认，不能沿用上一张券的门槛或排除规则计算。

所需只读权限分别为 `bss:DescribeCoupon` 和 `bss:DescribeCouponItemList`（资源 `*`）；费用中心或子账号还可能因折扣查询权限受限，按接口实际错误提示处理，不自行改权限。查询 API 不会领取、使用、冻结或验证实际结算抵扣。
